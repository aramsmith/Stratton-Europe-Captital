1. Change identifier and status

STRATTON-CC-002 proposes a Phase 3 overlay for a fixed GPT-5.6 portfolio and the EU Data Zone Standard inference posture. It does not rewrite the canonical Phase 3 design or either STRATTON-CC-001 candidate. Hash-bound AFF-A and AFF-B review and an explicit human decision remain required. No approval is claimed.

2. Human decision and reason for change

The governing specification records the human-selected direction: use the smallest governed model that meets the evidence threshold while retaining accountable human authority. Fixed Luna, Terra and Sol routes avoid flagship-model waste and opaque dynamic selection, preserve reproducibility and support route-specific evaluation.

3. Superseded regional-only statements

This overlay identifies, but does not edit, canonical statements that deny Data Zone deployment types. On a future explicit human decision for these exact bytes, those statements are superseded only for Azure OpenAI inference by section 4. Approved-location gates, private networking, the two-region recovery pattern and data-at-rest controls remain unchanged. Named resource locations do not promise the provider-selected inference processing region.

4. EU Data Zone Standard sovereignty boundary

The target deployment type is EU Data Zone Standard, SKU DataZoneStandard, with NoAutoUpgrade. Prompts and outputs remain within the EU Data Zone. Data at rest remains in the designated EU geography. Microsoft selects the processing region within that zone; the architecture does not promise a specific processing region.

Global Standard prohibited. Exact resource regions, quota, capacity, commercial terms and provider evidence are owner inputs. Production inference stays blocked pending the required authority evidence.

9. Security, privacy and compliance controls

AI, Search, Storage, SQL, Service Bus, Key Vault and configuration services retain private endpoints, central private DNS and public-network denial where supported. Every database remains publicly inaccessible. Workloads use separate managed identities, Microsoft Entra authorisation and least privilege.

Source authority, licence, purpose, classification, scan and admission precede analysis. Instructions and evidence are separated; cross-case retrieval, caller filters, citation spoofing and poisoned-index changes are denied and tested. Provider evidence must demonstrate the no-training-use boundary. Logs contain route metadata rather than sensitive bodies. Retention is owner-bound. GDPR, EU AI Act, DORA and source-licence evidence remain open controls; no legal classification or certification is provided.
