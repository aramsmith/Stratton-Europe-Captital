Verdict rationale

DIVERGES. The design has complete requirements/ABB/decision traceability, strong identity and assurance separation, bounded AI use and explicit inherited controls. Two security/compliance implementation defects remain: Azure SQL backup redundancy is not constrained against the default paired-region replication, and APIM private endpoint creation is not coupled to explicit public gateway disablement.

Both are MAJOR because they undermine approved sovereignty and private-ingress boundaries. This is architecture assurance, not approval, waiver, legal advice, certification or formal attestation.

Findings

AFFB-P3-R1-MAJ-001 — Azure SQL backup storage redundancy is not bound to the signed region pair

MAJOR · Manifest regeneration required

Evidence. The reliability contract and AFF-4 handoff require PITR/LTR and failover groups but omit SQL backup-storage redundancy. The Citadel contract rejects implicit Azure geo-pairs. Current Microsoft Learn states new Azure SQL databases default to GRS backup storage replicated to a paired region; LRS or ZRS is required to keep STR/LTR backups in-region.

Risk. Highly confidential backups can silently replicate outside the signed-approved pair, breaching SR-001, HD-003 and VAL-005 before runtime detection.

Bounded remediation. Add a no-default STR/LTR backup-redundancy parameter and assertion; require LRS/ZRS after capability and location evidence; allow GRS/GZRS only through a later explicit decision proving the paired location is approved. Validate rendered and deployed configuration before data admission.

Owners. AFF-3, General Counsel, DPO, CISO and AFF-4.

AFFB-P3-R1-MAJ-002 — APIM private endpoint is not coupled to explicit public gateway disablement

MAJOR · Manifest regeneration required

Evidence. SRC-AZ-019 says APIM public access is disabled after private DNS validation, but the network policy list omits APIM and the handoff outputs only its private endpoint. Microsoft Learn states public network access must be disabled separately after private endpoint configuration.

Risk. The public APIM gateway can remain reachable and bypass the private Application Gateway WAF and enterprise ingress path.

Bounded remediation. Require APIM publicNetworkAccess=Disabled in every environment after private endpoint approval and DNS proof; add APIM-specific policy, compile, PSRule and reachability evidence; prohibit public recovery fallback. Include App Configuration in the same explicit public-access review.

Owners. AFF-3, Network Lead, CISO, API platform owner and AFF-4.
