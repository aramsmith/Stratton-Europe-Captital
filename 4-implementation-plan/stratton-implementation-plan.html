Decision first

AFF-5 authors shared Bicep modules and only dev.bicepparam, tst.bicepparam and prd.bicepparam. Environment forks, floating modules, GitHub OIDC, stored credentials, public databases, public application ingress and Global/DataZone AI are prohibited.

Production remains blocked by exact tenant/subscription/identity, region, IPAM/WAN/DNS, SQL backup, retention/source/workload, support, model/provider and Internal Audit inputs. No value is selected by this plan.

No coding, deployment, Azure what-if or runtime testing occurred in Phase 4.

Open controls and release boundaries

Legal/regulatory

VAL-001, VAL-005, AFFB-RES-001 and AFFB-RES-002 block their DORA, location/transfer, AI classification and formal regulatory claim boundaries.

Acceptance/data

VAL-002 and VAL-003 block service, performance and Internal Audit validation. VAL-004 blocks production ingestion.

Rollback

Stop/scale/previous digest and forward correction are preferred. Destructive cleanup, failover, restore, role or immutability changes require explicit scoped approval; Internal Audit controls assurance cleanup.

Azure SQL accepts Geo, GeoZone, Local and Zone. Stratton production policy permits only explicit Local/Zone after capability evidence. The choice covers STR/LTR, affects future backups, can take up to 48 hours and removes geo-restore; approved failover groups provide cross-region recovery.

Every private endpoint has an explicit group ID, central zone, VNet link and resolver/forwarder path. DNS topology is never inferred.

Phase 5 local validation

AFF-5 pins tools, restores exact tags to cache, separately records OCI digests and runs format, lint, build, parameter consistency, policy/security, template/unit, deterministic-build, contracts, migrations, application and container checks, then creates a release manifest and content hashes. Phase 5 never deploys.

az bicep format --file $BicepFile --stdout
az bicep restore --file iac/infra/main.bicep --force
az bicep lint --file iac/infra/main.bicep
az bicep build --file iac/infra/main.bicep --outfile iac/out/main.json
Invoke-Pester -Path iac/tests -CI
Invoke-PSRule -InputPath iac/out -Module PSRule.Rules.Azure -Outcome Fail,Error
pwsh -NoProfile -File iac/validation/Capture-OciDigestEvidence.ps1
pwsh -NoProfile -File iac/validation/Invoke-LocalValidation.ps1 -Scope Release

Formatting uses stdout plus comparison and does not modify files. Restore creates a tag-keyed cache, not a lock/digest; digest capture is separate. Two byte-identical builds must hash identically. Application checks may be marked not applicable only when no application artefact exists; applicable checks cannot be silently skipped. Release content hashing uses an explicit sorted file set that excludes iac/release/content-hashes.json itself, preventing self-reference on rerun. Files are read by resolved full path, but evidence records normalised iac-relative paths in ordinal order so identical source trees reproduce the same output from different checkout locations. Canonical compact JSON is written as UTF-8 without BOM or a platform-specific trailing newline.

ARM validate, feature/provider/quota preflight and what-if are separate from local checks. Each requires Azure authentication and the exact tenant, management-group or subscription target permission. What-if remains separately authorised and is not mandatory without Azure access.

  --subscription $TargetSubscriptionId --template-file $EntryPoint `

Only a human with interactive sign-in, or separately invoked AFF-7 using the exact managed identity in its attempt authorisation, may execute. Values come from the approved hash-bound release/attempt manifest. GitHub OIDC and stored credentials are prohibited.

Every production stage captures before/after inventory, command output, deployment IDs, policy results and approvals. Failure stops downstream stages. Operations receives RB-001– RB-012, alert/rota ownership, telemetry/retention, identity, recovery, AI-change, first-three- deal and 20-deal controls. FinOps establishes a Pricing Calculator baseline only after exact region/capacity/commercial inputs; cost cannot weaken controls.

Executable AFF-5 handoff

  1. Create exactly the shared package structure and no environment fork.
  2. Implement the 17 units and application work package without changing Phase 3 intent.
  3. Preserve all 32 unknown parameters, 22 assertions, release constraints and seven controls.
  4. Restore/cache, inspect and separately capture digest evidence for each AVM candidate; return incompatibility to AFF-3.
  5. Make every documented local validation command executable and retain results.
  6. Create the hash-bound release manifest; stop on unknowns or any public/credential fallback.
