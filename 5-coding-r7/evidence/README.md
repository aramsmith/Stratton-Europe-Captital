# Phase 5 validation evidence

Evidence files in this directory are generated by local Phase 5 validation. Each record must include:

- command and working directory;
- start/end timestamps and exit code;
- exact tool version;
- redacted stdout/stderr or a path to raw redacted output;
- package or input hash;
- status `PASS`, `FAIL`, `BLOCKED` or `NOT_APPLICABLE` with a reason.

Do not place credentials, tokens, connection strings, document contents, personal data or unredacted
paths in evidence. Azure deployment, target validation, what-if and runtime cloud-test evidence do not
belong to Phase 5.

Historical runs may remain for local auditability. The frozen Phase 5 hash set includes only the
validation, container, source-security and dependency evidence referenced by its release manifest.

Every full run creates `evidence/local-validation/<run-id>/validation-input.json` before executing a
gate. It ordinal-sorts the package inputs, records each SHA-256 and byte length, and computes
`SHA256_UTF8_PATH_TAB_SHA256_TAB_SIZE_LF_V1`. Every step record, dependency record, source-security
summary, container summary, release manifest and freeze verifier must bind that exact aggregate.
Evidence is resolved only from the release manifest's explicit run ID and paths; filesystem
modification times are not evidence selectors.

For a full local run, `release-evidence` means release-manifest validation and generation only. The
retained validation index records `RELEASE_MANIFEST_ONLY` and the separate freeze sequence:
`New-BuildReport.ps1`, `New-Phase5Hashes.ps1`, then `Test-ReleaseEvidence.ps1`. The final hash
verification is not claimed as part of the full validation command.
